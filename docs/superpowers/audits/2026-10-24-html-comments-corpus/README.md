# HTML comments: corpus check

This is the acceptance check of [the spec](../../specs/2026-10-24-sec2md-html-comments-design.md) ("Corpus check"). It compares branch `fix/baba-mapping-gaps` against `main` at `2690d9f` on every document we hold, to show that the only output changes are comment text leaving the Markdown.

## Corpus and method

- **Corpus.** The same 2,217 distinct documents as the [positioned-layout check](../2026-10-24-positioned-layout-corpus/README.md):
  - the 10 fixtures;
  - Phase A's EDGAR cache;
  - the recent filings corpus;
  - every SEC original, retained exhibit and filing-index page in `E:\RCQWealth`, read only.
- **Conversion.** That check's `compare.py` converts each document on both sides, each side in its own process with its own `PYTHONPATH`. Each side is a source snapshot in scratch: `git archive 2690d9f`, and a copy of the branch's `src`. It compares page contents, page numbers and display pages, and the table completeness report.
- **Explanation.** [`explain.py`](explain.py) reads `compare.py`'s results and both sides' Markdown dumps. For each changed document it checks that:
  - no token is added;
  - the page numbers and display pages are the same;
  - every removed token occurs in the source's comments, as lxml parses them.

  A document that passes is "explained"; any other is listed for review.

```bash
python compare.py list --out docs.json --fixtures tests/fixtures/sec --phase-a-cache <main>/outputs/table-completeness-corpus --recent-cache <main>/outputs/recent-filings-corpus --vault E:/RCQWealth
PYTHONPATH=<git archive 2690d9f>/src python compare.py run --docs docs.json --out main.jsonl --dumps <scratch>/dumps-main --workers 12
PYTHONPATH=<branch src copy> python compare.py run --docs docs.json --out branch.jsonl --dumps <scratch>/dumps-branch --workers 12
python compare.py diff --main main.jsonl --branch branch.jsonl --out results.json
python explain.py --docs docs.json --results results.json --main-dumps <scratch>/dumps-main --branch-dumps <scratch>/dumps-branch --out explained.json
```

[`explained.json`](explained.json) holds every changed document with its verdict and causes. The dumps and `results.json` stay in scratch.

## Result

**Overall.**
- No conversion errors on either side.
- No document's table-check failures, reported tokens, structure findings or tables checked changed.
- 686 documents are identical.
- 1,531 documents changed, all in page content only:
  - by group: 4 fixtures, 5 vault primary documents and 1,522 vault exhibits and filing-index pages;
  - 1,529 are explained by the token rule above;
  - 2 needed review, and both are explained.

**The two reviewed documents.**
- **BABA's EX-99.1 (fixture).** Its pages gain display numbers. Pages 10 to 25 had `display=None` and now carry 10 to 25. The footer number used to sit between `Field: Sequence …` and `Field: /Sequence` text and is now a bare number. Pages 1 to 9 stay `None`, because a bare footer number below 10 is not taken as a page number (`_extract_page_number_from_content`, `min_val=10`). That rule is unchanged.
- **An AAPL 8-K exhibit** (`a-bjvizbd2etgmnic4.htm`, the 2025 notes indenture). The source writes `<a name="EXHIBITA"><!--Anchor--></a>EXHIBIT A`, which used to read `AnchorEXHIBIT A` and now reads `EXHIBIT A`. The token rule saw `EXHIBIT` as added, but it was the same word, unglued from the comment.
